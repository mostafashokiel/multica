プレイブックは、仕事が進むステージを並べた、名前とバージョンを持つリストです。エージェントが 1 ステップを実行し、人が承認し、条件が分岐を選び、終了ステージが締めくくります。プロセスを 1 か所に一度だけ定義し、[スクワッド](/squads)のリーダーがタスクをその通りに進めます。

プレイブックは、プロジェクトボードで課題を列から列へ引き継ぐプロジェクトのワークフロー（**設定 → ワークフロー**）とは別物です。プレイブックは、承認、条件、並列ステップを含むプロセス全体を記述し、スクワッドリーダーがそれに従います。

<Callout type="info">
プレイブックは機能フラグ `workflows_v1` の背後にあり、デフォルトでは無効です。セルフホスト環境では `FF_WORKFLOWS_V1=true` で有効にできます。無効の間は、プレイブックのページも API も表示されません。
</Callout>

プレイブック自体は自動で動きませんし、Multica に専用の実行エンジンもありません。プレイブックを**適用**すると、スクワッドのリーダーの指示に手順書が書き込まれ、リーダーがそれに従います。ページに表示されるのはリーダーが記録した状態であり、強制ではありません。

## ステージ

| ステージ | 役割 |
|---|---|
| **エージェント** | エージェントが作業します。リーダーは `@` メンションで依頼し、返信を待ちます。 |
| **並列** | 2〜8 のエージェントが同時に作業します。リーダーはブランチごとにサブタスクを 1 つ作って担当エージェントに割り当て、すべてが Done になったらタスクを先へ進めます。 |
| **人による承認** | 1 人以上が判断します。承認者グループ、任意の差し戻し上限、任意の再確認までの時間を指定できます。 |
| **条件** | タスクのラベルから次のステージを選びます。例: `has_label("pci-scope")`。 |
| **終了** | プレイブックを終えます。 |

承認には「承認」と「却下」の 2 つの出口があります。却下は、差し戻し上限まで前のステージに戻ります。

## プレイブックを設計する

サイドバーの**プレイブック**を開きます。オーナーと管理者は作成・編集でき、それ以外のメンバーは閲覧のみです。

- パレットからステージの種類をキャンバスにドラッグし、ハンドル間をドラッグして接続し、選択したステージを右のパネルで編集します。エージェントや人はワークスペースから選びます。
- 編集中、サーバーがプレイブックを検証してすべての問題を一覧にします。問題のあるバージョンは保存できますが、適用はできません。
- 保存するたびに不変の新しいバージョンが作られます。古いバージョンを元にした保存は、他の人の変更を上書きせずに競合として拒否されます。古いバージョンは新しいバージョンとして復元できます。
- プレイブックの名前（一覧とそのページに表示）は、プレイブックのページの**名前を変更**で変えます。定義の一部ではないので新しいバージョンは作られず、キーも変わりません。

## プレイブックを別のワークスペースや環境へ移す

プレイブックはプレーンテキストです。プレイブックのページで**ダウンロード**または**コピー**を選ぶと YAML が得られます。移行先のワークスペースで、プレイブック一覧の**YAML をインポート**（または任意のプレイブックの **YAML** タブ）を選び、テキストを貼り付けるかファイルを読み込んで、**キャンバスに反映**を選びます。サーバーがテキストを読み取り、問題を行番号付きで表示します。結果は元に戻せる 1 回の変更で、保存するまで何も保存されません。

- 新しいプレイブックとしてインポートする場合、テキスト中のキーがそのままキーになります。既存のプレイブックにバージョンを追加するには、テキストのキーがそのプレイブックのキーと一致している必要があります。
- エージェントと人はテキスト中に名前で書かれ、適用先のワークスペースで検索されます。エージェント名は完全一致が必要で、承認者は `user:<id>` と書かれ、ワークスペースごとに異なります。適用前に置き換えてください。

## プレイブックのアーカイブと削除

プレイブックのページで、オーナーと管理者は**アーカイブと削除**を使えます。**アーカイブ**すると一覧から隠れ（**アーカイブを表示**で再表示）、編集と適用ができなくなります。すでに従っているスクワッドの手順書とタスクのラベルはそのままです。**元に戻す**で取り消せます。**完全に削除**できるのはアーカイブ済みのプレイブックだけで、キーの入力が必要です。すべてのバージョンと履歴が削除され、元に戻せません。スクワッドがまだ従っているプレイブックは削除できません。先にそのスクワッドへ別のプレイブックを適用するか、指示からそのブロックを取り除いてください。

## 実行にかかる時間

Multica は、各タスクが各ステージに入った時刻と出た時刻を記録し、すでに保持しているエージェントの実行記録とコメントと組み合わせて計算します。

- **パイプライン：**各カードに、そのステージに何時間いるか（人による承認では**待機**）、ここまでの合計、そしてステージの通常の 3 倍を超えた場合の印が表示されます。終わった滞在が 2 件以上あると、レーンに通常の時間が表示されます。並列ステージでは各ブランチの時間が表示されます。カードの**タイムライン**から実行全体を開けます。
- **実行タイムライン：**プレイブックに従うタスクのサイドバーの**実行タイムライン**にもあります。合計を**エージェントの作業**、**人の待ち時間**、**引き継ぎ**に分け、各ステージを共通の時間軸上のバーで示し、並列ブランチと節約できた時間も表示します。
- **インサイト：**プレイブックのページのタブです。直近 7、30、90 日に始まった実行について、ステージごとの標準時間と遅い方 10% の時間、ゲートの差し戻し回数、最も時間がかかるステージ、各エージェントの標準的な実行時間、各承認者の標準的な待ち時間を表示します。

数値の出し方：エージェントの時間はクリティカルパス上の作業時間で、並列ステージでは最も遅いブランチです。人の待ち時間は、そのゲートでの最初のコメントで終わります（承認者グループに実際の `user:<id>` で載っている必要があります）。リーダーが反応した時点ではありません。引き継ぎは残りで、リーダー自身の作業とステップ間の隙間です。時間は終日カウントされるため、週末を挟んだゲートは週末分が含まれます。記録を始める前の実行は、リーダーの「Moved from … to …」コメントから補われます。

## プレイブックをスクワッドに適用する

プレイブックのページで**スクワッドに適用**を選びます。ダイアログには、リーダーが受け取る手順書そのものと、使用するラベルが表示されます。適用すると次のことが行われます。

- スクワッドの指示の中の 2 本のマーカー行の間に手順書を書き込み、残りの文章はそのままにします。同じバージョンをもう一度適用しても何も変わりません。
- ステージが指定するエージェントと、承認者グループのメンバーをスクワッドのメンバーに追加し、見つからなかったものを知らせます。
- 承認者がリーダーを起こせない場合や、他の人専用の非公開エージェントを呼び出せない場合に警告します。Multica は、連鎖を始めたコメントの投稿者として権限を確認するため、プレイブック内のすべてのエージェントをすべての承認者が実行できる必要があります。[エージェント](/agents)を参照してください。

適用してもラベルは作成されませんが、事前に作る必要もありません。スクワッドに割り当てられたタスクはすべてプレイブックに従い、リーダーが `wf:<key>` と各ステージの `phase:<stage>` ラベルを自分で付け、ワークスペースにないものは作成します。ダイアログに一覧が表示されます。

## タスクをプレイブックに通す

タスクに `wf:<key>` ラベルを付け、そのプレイブックに従うスクワッドに割り当てます。リーダーはタスクの `phase:` ラベルを現在のステージに設定し、エージェントのステージは `@` メンションで依頼し、返信があればタスクを進めます。その間、タスクは常にスクワッドに割り当てられたままです。

人による承認のステージでは、リーダーは承認者にメンションして待ちます。承認者はタスクに自分の言葉で返信するだけで判断できます。ラベルも、スクワッドへのメンションも不要です。リーダーは一覧にある承認者のコメントにだけ反応します。明確な承認ならタスクを進め、明確な拒否なら理由を添えて差し戻し、それ以外なら 1 度だけ確認の質問をします。

並列ステージでは、リーダーがブランチごとにサブタスクを作り、そのブランチのエージェントに割り当てるため、全員が同時に始まります。各エージェントは自分のサブタスクを **Done** で終えなければなりません。Multica がリーダーを再び起こすのはサブタスクが Done か Cancelled になったときだけで、In Review で止まるとリーダーは待ち続けます。手順書は各サブタスクにその旨を書き込みます。最後のサブタスクが Done になると、リーダーは結果を読んでタスクを先へ進めます。サブタスクが取り消された場合や、エージェントが作業できない場合は、人が判断するまでステージは止まります。

## パイプライン

サイドバーの**パイプライン**は、1 つのプレイブックのタスクをステージごとに列で表示します。スクワッドで絞り込んだり、どのスクワッドにも割り当てられていないタスクだけを表示したりできます。人による承認のステージには、誰を待っているかが表示されます。フェーズラベルがない、複数ある、どのステージにも一致しないタスクは別に一覧されるので、修正しやすくなっています。 並列ステージでは、タスクのカードに完了したブランチ数も表示され、ブランチごとの行からサブタスクを開けます。
