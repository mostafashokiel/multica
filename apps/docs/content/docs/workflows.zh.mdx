工作流是一份有名称、有版本的阶段清单，描述工作如何流转：由智能体完成一步，由人审批，由条件选择分支，最后由结束阶段收尾。它把流程只定义一次、集中放在一处，再由[小队](/squads) leader 带着任务走完。

<Callout type="info">
工作流受 `workflows_v1` 功能开关控制，默认关闭。自托管部署可通过 `FF_WORKFLOWS_V1=true` 开启。关闭时，工作流页面和 API 都不会出现。
</Callout>

工作流本身不会自己运行，Multica 也没有单独的执行引擎。**应用**工作流会把一份说明写入小队 leader 的指令，由 leader 照着执行。页面展示的是 leader 记录下来的状态，并不强制执行。

## 阶段

| 阶段 | 作用 |
|---|---|
| **智能体** | 由智能体完成工作。leader 通过 `@` 提及把工作交给它，然后等待它回复。 |
| **并行** | 两到八个智能体同时工作。leader 为每个分支创建一个子事项并分配给对应的智能体，所有子事项都完成（Done）后再推进任务。 |
| **人工审批** | 由一个或多个人来决定。工作流会指定审批人分组，可选的返工上限，以及可选的再次催办时间。 |
| **条件** | 根据任务的标签选择下一阶段，例如 `has_label("pci-scope")`。 |
| **结束** | 结束工作流。 |

审批有两个出口：通过和驳回。驳回会回到更早的阶段，直到达到返工上限。

## 设计工作流

在侧边栏打开**工作流**。所有者和管理员可以创建和编辑，其他人只能查看。

- 从调色板把阶段类型拖到画布上，在连接点之间拖动即可连线，并在右侧面板编辑选中的阶段。智能体和人员都从你的工作区中选择。
- 编辑时服务器会检查工作流并列出所有问题；有问题的版本可以保存，但不能应用。
- 每次保存都会生成一个不可变的新版本。基于过期版本的保存会被当作冲突拒绝，而不是覆盖他人的修改。旧版本可以恢复为新版本。
- 工作流的名称（显示在列表和其页面上）通过工作流页面上的**重命名**修改；它不属于定义，因此重命名不会产生新版本，键也不会改变。

## 把工作流移到另一个工作区或环境

工作流是纯文本。在工作流页面点击**下载**或**复制**即可得到它的 YAML。在目标工作区的“工作流”页面选择**导入 YAML**（或打开任一工作流的 **YAML** 标签页），粘贴文本或加载文件，然后选择**放到画布**。服务器会读取文本并列出问题及其所在行；结果是一次可撤销的修改，保存之前不会存储任何内容。

- 作为新工作流导入时，文本中的键就是新工作流的键。要给已有工作流添加版本，文本中的键必须与该工作流一致。
- 智能体和人员是以名称写在文本里的，会在你应用它的工作区中查找。智能体名称必须完全一致，审批人写作 `user:<id>`，在不同工作区里并不相同：应用前请替换。

## 把工作流应用到小队

在工作流页面选择**应用到小队**。对话框会显示 leader 将收到的完整说明以及用到的标签。应用时会：

- 把说明写在小队指令中的两行标记之间，其余文字保持不变；重复应用同一版本不会有任何改变；
- 把各阶段指定的智能体和审批人分组中的成员加入小队成员，并告诉你哪些找不到；
- 当某位审批人无法唤醒 leader、或无法调用某个智能体（因为它对其他人是私有的）时给出警告。Multica 以发起这条链路的评论者的身份检查权限，因此工作流中的每个智能体都必须能被每位审批人运行。参见[智能体](/agents)。

应用不会创建标签，也不需要你事先创建：分配给该小队的每个任务都会按工作流执行，leader 会自己添加 `wf:<key>` 和各阶段的 `phase:<stage>` 标签，工作区里还没有的会自动创建。对话框会列出这些标签，方便你了解。

## 让任务走完工作流

给任务加上 `wf:<key>` 标签，并分配给遵循该工作流的小队。leader 会把任务的 `phase:` 标签设为当前阶段，通过 `@` 提及把智能体阶段委派出去，并在智能体回复后推进任务。整个过程中任务始终分配给小队。

到了人工审批阶段，leader 会提及审批人并等待。审批人直接在任务下用自己的话回复即可，不需要标签，也不需要提及小队。leader 只响应列表中审批人的评论：明确同意就推进，明确拒绝就带着理由退回，其他情况只会追问一次。

在并行阶段，leader 会为每个分支创建一个子事项并分配给该分支的智能体，让它们同时开始。每个智能体都必须把自己的子事项做到 **Done**：只有子事项变为 Done 或 Cancelled 时 Multica 才会再次唤醒 leader，停在 In Review 会让 leader 一直等下去。说明会在每个子事项里写明这一点。最后一个子事项 Done 后，leader 读取各分支的结果并推进任务。若有子事项被取消，或智能体无法完成工作，该阶段会停下来等待人来决定。

## 流水线

侧边栏的**流水线**按阶段展示某个工作流的任务，每个阶段一列。可以按小队筛选，或筛选未分配给任何小队的任务。人工审批阶段会注明在等谁。没有阶段标签、有多个标签、或标签对不上任何阶段的任务会单独列出，方便修正。 在并行阶段，任务卡片还会显示其分支完成了几个，并为每个分支列出一行，点击即可打开对应的子事项。
